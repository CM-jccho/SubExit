# 입력 팝업·화면 안정성 수정

2026-09-17. 기준: main `16c0538` + PR #58의 복사·저장 보완.

## 확인과 판단

소스에서 대화 수가 바뀔 때마다 자동 스크롤하고, 상대 답변 대기 여부에 따라 입력 컴포넌트를 제거했다가 다시 만드는 구조를 확인했다. 화면 높이와 입력 상태가 함께 바뀌므로 사용자가 느끼는 흔들림의 원인 후보로 판단했다. 실제 휴대폰에서 보고된 깜빡임을 재현한 결과는 아니다.

## 적용한 동작

- **대화 연습·AI 대화·녹음 기록:** 평소에는 작성·녹음 버튼만 표시한다. 입력 버튼 또는 답변 후보를 누르면 팝업을 연다. 녹음·파일·문자 입력은 팝업 안에서 진행한다.
- **메시지 답장:** 상대 메시지·조건 입력과 답장 작성을 팝업으로 분리한다. 저장 후에는 읽기 전용 답장과 복사·수정 버튼이 남는다. 복사가 차단되면 답장 팝업을 열고 텍스트를 선택해 수동 복사를 돕는다.
- **완료와 실패:** 저장 성공 후 팝업을 닫는다. 상대 AI 응답까지 기다리며 입력 화면을 붙잡아두지 않는다. 저장 실패 시 입력과 오류 안내가 팝업에 남는다. 연속 클릭으로 중복 저장하지 않는다.
- **작성 중 닫기:** 저장하지 않은 초안은 같은 화면 안에서 잠시 유지하고 ‘입력 이어쓰기’ 또는 ‘답장 수정’으로 다시 연다. 닫기 자체는 영구 저장이 아니다. 화면 이동·새로고침에는 미저장 확인을 적용한다.
- **안정성:** 입력 컴포넌트를 응답 대기마다 재생성하지 않는다. 대화가 추가될 때 페이지를 자동 스크롤하지 않는다. 팝업은 배경 스크롤을 잠그고, 닫을 때 이전 포커스와 스크롤 잠금을 복원한다. 시각적 뷰포트 높이 변화에 맞춰 팝업 높이를 제한한다. 별도의 등장·퇴장 애니메이션은 넣지 않았다.

첫 상황 설정, 용어 편집, 일상 대화 등 다른 기능의 모든 입력을 일괄 팝업화한 것은 아니다. 이번 범위는 대화 작업 화면과 메시지 답장의 상시 입력 영역이다.

## 검증

전체 단위·API 계약·JSDOM UI 통합 테스트 **139개 통과, 실패 0개, 건너뜀 0개**. 최종 테스트 로그에 오류·React 경고 없음. 프로덕션 빌드 및 타입 검사 통과.

이번에 추가한 4개 테스트에서 확인한 연결 동작:

1. 반복 입력·뷰포트 크기 변경 중 같은 입력 DOM과 포커스 유지, 팝업 재열기 없음, Escape 후 포커스·스크롤 잠금 복원.
2. 초안 작성 → 닫기 → 이어쓰기 → 연속 저장 클릭 → 저장 중 Escape 차단 → 실패 시 초안 유지 → 재시도 성공 시 닫기 → 다음 작성은 빈 입력.
3. 메시지·목표 입력 → 팝업 닫힘 → 답장 작성 → 임시 닫기 → 재열기 → 저장 → 읽기 전용 기록 → 복사 차단 시 입력 팝업과 전체 선택 복구.
4. 실제 대화 컴포넌트에서 내 답변 저장 → AI 응답 대기 중 팝업 닫힘 → 응답 도착 후에도 같은 입력 컴포넌트 유지 → 다음 입력 초기화 → 닫아둔 미저장 초안의 목록 이동 취소·승인.

기존 메신저·녹음·후보·저장·오류·한도 테스트는 새 팝업 진입 절차에 맞춰 유지했다. 가상 DOM이 지원하지 않는 dialog 열기/닫기는 테스트 대역이며, IndexedDB와 AI도 기존 테스트 대역을 사용한다. 실제 브라우저의 모달 차단·히스토리·모바일 키보드 동작까지 이 결과로 보장하지 않는다.

## 남은 확인

브라우저 점검은 앞선 자동 승인 검토의 Codex 사용 한도 오류로 실행이 차단되어 실제 화면 검증을 완료하지 못했다. 승인 검토를 다른 브라우저 도구로 우회하지 않았다.

운영 배포 후 iPhone Safari와 Android Chrome에서 입력·키보드 열기/닫기·한글 조합 중 커서 유지·팝업 내부 스크롤·닫기 후 원래 화면 위치를 확인해야 한다. 녹음 권한 허용/거부, 녹음 중지 후 변환, 파일 선택, 저장 실패 복구도 실제 기기에서 확인해야 한다. 이 검증 전에는 ‘깜빡임 완전 해결’로 표시하지 않는다.

이번 수정은 PR에 보관하며 운영 배포 완료를 의미하지 않는다. Vercel 제한 해제 시각도 이번 작업에서 재확인하지 않았다.
