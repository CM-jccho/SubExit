# 금전 부탁 거절 — 원인 및 검증 기록

확인일: 2026-09-18 한국 시간 오후 3시경

## 확인한 원인

- 제보 문장 “확인되지 않은 조건까지 약속드리기는 어려워요.”는 `data/demo-responses.json`의 `decline.hints`에 저장된 문장과 정확히 일치했다.
- `sampledRequest`는 일일 한도·연결 오류 또는 수동 샘플 모드에서 사전 작성 응답을 반환한다. 이 문구가 나왔다는 사실만으로 당시의 오류 종류까지 단정할 수는 없다.
- 운영 API에 가상의 금전 부탁 거절 입력을 한 번 전송했다. 실제 응답은 HTTP 429, `provider_rate_limit`, `quotaKind: daily`, `retryAt: 2026-09-18T07:00:00.000Z`였다. 추가 AI 호출은 중단했다.
- 일반 거절 샘플이 거절 대신 조건 확인·추후 판단을 암시했다. 샘플 선택 시 카드 내용에 상대의 최신 발화가 항상 포함되지 않았고, 지킬 선도 빠져 있었다.

## 수정

1. 금전 대여 요청과 거절 의도가 함께 있는 경우에만 금전 부탁 거절 예시를 선택한다.
2. 차용을 부탁하는 사용자, 빌린 돈의 반환 일정, 책 대여 거절, 거절하지 않고 도와주려는 경우를 금전 거절로 분류하지 않도록 회귀 검증했다. 키워드 방식이므로 모든 언어적 맥락을 이해하는 것은 아니다.
3. 일반 거절 샘플에서도 모호하게 미루는 표현을 명확한 거절로 바꿨다.
4. 예시 선택에 상대의 최신 말과 지킬 선을 포함한다.
5. 답변 바로 위에 ‘AI 답변을 받지 못해 미리 작성한 예시를 보여드려요. 현재 대화를 분석한 결과가 아니에요.’를 펼쳐서 표시한다. 수동 예시 모드는 별도 문구를 쓴다.
6. 실제 AI 지시에도 금전 거절 목표, 이유 날조 금지, 미래 대여 약속 금지, 관계에 맞는 말투를 명시했다.

예시: “미안하지만 돈을 빌려주기는 어려워요. 이해해 주셨으면 해요.”

## 검증 범위와 남은 확인

- 자동 테스트 205개 통과. 그 안의 장애 시뮬레이션은 13개 상황 × 4개 기능 × 15개 장애 조건 = 780개 조합이며 모두 모의 응답이다.
- 실제 HTTP 429를 모의 재현하는 UI 회귀 테스트에서, 카드에 금전 언급이 없어도 상대 발화와 거절 목표를 함께 반영하고 예시 전환 안내가 접히지 않는 것을 확인했다.
- 프로덕션 빌드 통과. 최종 배포에서도 빌드 상태와 운영 도메인 연결을 확인한다.
- 실제 Gemini 생성 품질은 일일 한도 때문에 미검증이다. 프롬프트를 보강했다는 사실은 품질 통과를 뜻하지 않는다.
- 브라우저 연결이 불안정하여 실제 모바일·데스크톱 화면 검증은 완료하지 못했다.
- **제출 준비 완료로 판정하지 않는다.** 한도 해제 후 실제 AI 생성 응답과 모바일 입력 흐름을 확인해야 한다.

## 마지막 수동 시뮬레이션

1. 사이트를 새로고침하고 ‘답변 추천받기’ → 직접 입력을 연다.
2. 상대 말: ‘이번 주에 돈을 조금 빌려줄 수 있어?’ / 상대: 친구 / 목표: ‘돈을 빌려달라는 부탁을 정중하게 거절하기’ / 지킬 선: ‘나중에 빌려주겠다고 약속하지 않기’.
3. 샘플 모드에서 명확히 돈 대여를 거절하는 문장과 ‘예시’ 안내가 보이는지 확인한다.
4. 샘플 모드를 끄고 동의 후 같은 입력을 보낸다. 반드시 결과가 **AI 제안**인지 확인한다. ‘샘플’이면 실제 AI 품질 검증으로 세지 않는다.
5. 응답에 거절이 직접 포함되는지, 조건 확인·추후 대여·근거 없는 경제 사정·대출 권유가 없는지 확인한다.
6. 상대 말을 ‘조금만 빌려줘도 안 돼?’로 바꿔 다시 요청해도 거절 목표와 지킬 선이 유지되는지 확인한다.
7. 반대 상황 ‘내가 친구에게 돈을 빌려달라고 부탁하고 싶다’에서는 역할이 뒤집혀 거절 답변이 나오지 않는지 확인한다.
8. 친구 약속 조정과 직장 일정 조정도 각각 한 번 확인한다. 호출 한도가 다시 나오면 중단한다.
