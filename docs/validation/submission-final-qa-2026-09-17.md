# 스픽코칭 최종 통합 점검 — 2026-09-17

## 판정: AI 시연 제출은 보류

일반 입력·샘플 연습·저장은 동작하지만, 운영 Gemini 요청 5종이 모두 일일 한도 초과(HTTP 429)로 실패했다. 실제 AI 성공 응답과 모바일 실기기 음성·키보드 검증이 남아 있으므로, “웹·모바일 전체 통과 / 제출에 문제 없음”으로 판정하지 않는다.

## 이번 수정

1. 온보딩을 제외한 화면 스와이프 이동과 관련 전환 CSS 제거. 일반 화면은 메뉴·버튼으로 이동한다. 세로 스크롤·브라우저 기본 제스처는 막지 않는다.
2. 온보딩은 손가락을 따라 움직이는 카드 전환, 짧은 드래그 복귀, 다음/시작 버튼 구분을 유지한다.
3. 운영 브라우저에서 발견한 “내 기록에서 저장 대화를 다시 열면 ‘내 기록으로’가 동작하지 않음” 수정. 이미 records 화면인 경우 부모의 동일 경로 이동에 맡기지 않고 내부 선택을 해제한다. 미저장 입력 확인·요청 취소·음성 정리는 유지한다.
4. 일반 화면 스와이프 비활성화를 320/375/390/430/768px 모의 폭으로 회귀 검증. 저장 대화 재열기→목록 복귀 테스트 보강.
5. 자작 가상 데이터만 사용하는 운영 API smoke script 추가: `scripts/smoke-production.cjs`.
6. 추가 피드백 반영: 답변 후보 문장 탭은 즉시 전송, 별도 ‘고쳐 쓰기’는 편집 후 전송. 미완성 초안/음성이 있으면 교체 여부 확인, 저장 실패 시 문장 보존, 이중 탭 중복 전송 차단.
7. 대화와 답변 입력을 하나의 배경 안으로 통합. 전송하면 키보드를 닫고 새 말풍선으로 스크롤/포커스 이동. 상대 응답 대기 표시와 최소 550ms 간격 적용(이미 느린 응답에 추가 550ms를 더하지 않음).
8. 이전 버튼을 테두리·아이콘이 있는 공통 스타일로 정리하고 보조 연습 메뉴를 접음. 중복 안내 토스트 제거.
9. 샘플/미동의 상태의 효과 없는 음성 재시도 버튼을 숨기고 AI 모드 전환/동의를 먼저 안내. 가능 상태에서는 ‘다시 문자로 바꾸기’로 명확히 표시.
10. 화자 미지정/내 말 없음 상태는 코칭 버튼 앞에서 바로 수정 가능. ‘전부 내 말로’ 또는 화자 위치로 이동 제공. 확인 체크만으로 미지정 화자를 통과시키지 않음.

## 제출 전 남은 필수 확인

- [ ] Gemini 한도 확보 후 실제 힌트·상대 답변·후보 3개·용어 추출·독백 코칭 성공 확인. 반복 호출보다 프로젝트 할당량 상태를 먼저 확인한다.
- [ ] iPhone Safari: 기록 작성/답장/상황 수정/용어 메모에서 키보드 열기·닫기, 라벨/닫기/저장 버튼 가림 확인. 작은 화면·가로 회전 포함.
- [ ] Android Chrome: 동일 입력 흐름과 뒤로가기 확인.
- [ ] 두 실기기에서 자작 음성 10초 녹음→재생→문자 변환→수정→저장→재열기. 권한 거부 후 복구 포함.
- [ ] 실시간 듣기는 지원 브라우저에서 말이 추가되는 동안 처리·중지·재시작 검증. 미지원 브라우저의 직접 입력/짧은 녹음 대안 확인.
- [ ] 실제 30분/50MB 경계 파일, 손상 파일, 화면 잠금·통화 인터럽트는 별도 실기기 검증. 단위 테스트만으로 통과 처리하지 않는다.
- [ ] 발표 직전 사용할 URL에서 직접 시연. 서버 상태 200만으로 AI 사용 가능 여부를 판단하지 않는다.

## 운영상 주의

- 두 Render 주소는 같은 앱 코드를 배포하는 별도 서비스다. 기기 내 기록은 주소(origin)에 따라 분리되므로 제출·시연 URL을 하나로 통일한다.
- 현 서비스 설정은 free이다. 장시간 미접속 뒤 기동 지연 가능성을 발표 동선에 고려한다. 이번 점검에서 요금 변경이나 유지용 주기 호출은 설정하지 않았다.
- 실제 AI가 막힌 상태를 샘플로 조용히 감춰 정상 작동처럼 시연하지 않는다. 샘플은 사전 작성 예시임을 표시한다.

이 보고서는 실행한 범위의 증거와 미검증 경계를 구분한다. 모든 기기·모든 엣지케이스를 보장하는 인증서가 아니다.
