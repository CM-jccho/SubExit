# 네 가지 목적 중심 앱 구성

2026-09-17. 기준: Render 배포 브랜치 `deploy-render-20260917`의 6406a3a 위 변경.

## 변경한 구조

- 홈: 대화 연습 / 메시지 답장 / 대화 기초 훈련 / AI 요청 연습. 네 개의 카드와 최근 개인 기록 한 건 이어하기. 샘플은 최근 개인 기록에서 제외.
- 공통 메뉴: 홈 / 내 기록 / 더보기. 모바일에서는 세 칸 하단 메뉴.
- 목적을 먼저 선택한다. 관심 상황은 대화 연습 안에서만 선택한다. 메시지 작성·훈련·AI 요청·더보기 도구에 관심 상황 선택을 강제하지 않는다.
- 목적별 화면에는 ‘홈으로’와 현재 기능명만 표시한다. 이전 네 탭을 다시 반복하지 않는다.
- 더보기: 용어 노트 / AI 대화 상대 / 가볍게 이야기하기 / 사용·저장 안내. 기초 훈련·AI 요청을 중복 배치하지 않는다.
- 대화 연습의 ‘내 녹음으로 복기’는 새 녹음 화면을 직접 연다. ‘연습 상대 선택’은 AI 대화 상대 공간으로 연결한다.
- 내 기록: 연습·메시지 답장·기초 훈련·AI 요청 결과·녹음을 모아서 다시 연다.
- 튜토리얼은 대화 연습 안에서 시작한다. 첫 홈에서 특정 상황을 먼저 고르게 하지 않는다. 도움말로 재실행 가능.
- ‘모든 상황’을 고른 뒤 ‘아직 정하지 않음’이라고 보이던 문구도 수정했다.

## 더보기 중복 원인

기초 훈련과 AI 요청이 내 대화의 공통 네 탭과 더보기 카드에 중복 존재했다. 주 메뉴 선택 표시도 library/messenger/more/records로 분산돼 있었다. primary section(홈·기록·더보기)과 URL 복원 목적지를 분리했다. 네 가지 기능과 더보기 도구가 실제로 서로 다른 콘텐츠를 여는지, 새로 마운트했을 때 해당 화면이 복원되는지 검사했다.

- 대화 연습에 들어간 뒤 관심 선택 → 전체 분야 보기 → 선택 유지 → 검색·개인 카드·삭제 상태 유지.

## 운영 반영 상태

소스는 Render가 사용하는 브랜치에 올린다. Render 관리 연결은 아직 없고 저장소 설정은 자동 배포 off이므로 이 문서는 운영 반영 완료를 뜻하지 않는다. Render 대시보드에서 ddeundeun-call-render 서비스의 연결 브랜치가 deploy-render-20260917인지 확인한 뒤 Manual Deploy → Deploy latest commit을 실행해야 한다. 키를 다시 등록하거나 사이트를 새로 만들 필요는 없다. 배포 후 홈 네 카드, 하단 세 메뉴, 더보기 네 보조 도구와 각 링크를 확인한다.
