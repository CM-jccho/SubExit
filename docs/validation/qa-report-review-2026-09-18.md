## 검증 결과와 범위

- 전체 자동 테스트: **202 통과 / 0 실패 / 0 건너뜀**. 이번 추가 4개.
- 프로덕션 빌드·타입 검사: 통과.
- 코드 diff 공백 검사: 통과.
- 테스트는 JSDOM, 가짜 미디어 장치/시간, mock API를 사용합니다. 실제 마이크·스피커·모바일 키보드 검증이 아닙니다.
- 현재 브라우저 연결은 탭 조회에서 20초 timeout. 가능한 브라우저 목록에는 Chrome이 있으나 제어 연결은 복구되지 않았습니다.
- 앞선 실제 Gemini 성공(서버 처리 1.563초)은 당시의 1회 성공입니다. 이후 한도 초과가 발생했으므로 현재 전체 AI 정상 동작의 근거로 사용할 수 없습니다.

## 배포 뒤 사람이 확인할 순서

1. **입력 분리(P05, 최우선)**: 새로고침 → 지금 대화 도움받기 → `왜 이제 약속을 바꾸자는 거야?` 입력 → 상대·목표 조정 열기 → 상대 `친구`, 원하는 결과 `가능한 시간을 물어보고 약속을 다시 정하기`, 지킬 선 `확정하지 않은 날짜는 약속하지 않기`를 각 필드에 직접 클릭·입력. 각 단계마다 상대 발화가 바뀌지 않았는지 확인. AI 또는 명시적 샘플 결과 후 최근 추천의 상대 발화도 확인. 자동화 시 좌표 재사용 대신 고유 name/id와 실제 포커스 요소를 확인.
2. **권한 보류/취소**: 마이크 권한 팝업에 응답하지 않기. 대기 중 '기다리지 않고 직접 입력'이 동작하고 초안이 보존되는지 확인. 별도 시도에서 15초 뒤 대기 종료/직접 입력 복구 확인. 종료 후 뒤늦게 허용해도 녹음이 시작되지 않아야 함. 팝업 자체는 브라우저 권한 UI이므로 앱이 강제로 닫을 수 없음.
3. **모달 키보드**: 사용법 열기 → Tab 반복/Shift+Tab → 버튼 안에서 순환 → Escape → 열었던 도움말 버튼으로 복귀. 입력 모달의 disabled 버튼과 접힌 상세 항목으로 포커스가 들어가지 않는지 확인.
4. **실제 화면 폭**: 1440×900, 1024×768, 360×640, 390×844에서 홈/온보딩/도움말/빠른 도움/연습 준비 확인. CSS로 body만 좁히지 말고 브라우저 viewport 자체를 설정. document 폭, window.innerWidth, matchMedia('(max-width: 700px)')를 함께 기록. 모달 전체·닫기·하단 CTA 접근 확인.
5. **실제 기기**: iPhone Safari/Android Chrome에서 마이크 허용 → 5초 녹음 → 재생 → 문자 변환. 키보드가 열린 상태에서 라벨/완료 버튼 확인. 카카오 인앱은 별도 결과로 기록.
6. **AI 재검증**: 한도 복구 뒤 빠른 도움 → 연습 후보 → 용어 찾기 → 녹음 문자 변환·코칭을 가상 데이터로 실행. source=ai 확인. 샘플 성공과 구분. 한도에 다시 막히면 반복 호출하지 않고 제출 판단 보류.
