# 든든콜 버튼 동작·통합 재검증

검증일: 2026-09-17  
기준: `CM-jccho/SubExit`의 최신 main `16c05385193052b809eda60b069f5730f1f240c1` + 이 변경 묶음  
운영 주소: https://wanted-sidecue.vercel.app/

## 판정

자동 테스트 **135개 통과, 실패 0개, 건너뜀 0개**, 프로덕션 빌드와 빌드 내 타입 검사 통과.
이 수치는 단위 테스트·API 계약 테스트·JSDOM 기반 UI 통합 테스트의 합계다. 실제 브라우저 E2E 135개를 실행했다는 의미가 아니다.

복사·저장 결과 안내와 미저장 이동 보호를 수정했다. 실제 브라우저와 운영 배포 검증은 완료하지 못했으므로, **모든 환경에서 정상 작동한다고 판정하지 않는다.**

## 발견한 문제와 조치

1. **복사·저장 완료/실패 안내가 버튼에서 멀리 떨어진 화면 상단에만 표시됐다.** 데이터 처리가 끝나도 사용자가 결과를 알아보기 어려웠다. 답장 버튼 바로 아래에 처리 중·완료·오류 안내를 배치하고 버튼도 `복사 중… / 복사 완료`, `저장 중… / 저장됨`으로 바꿨다. 실제 Promise 완료 전에 성공을 표시하지 않는다.
2. **복사가 차단되면 관계없는 AI 예시 안내까지 표시될 수 있었다.** 복사 오류를 별도로 처리하고, 답장 전체 선택과 길게 누르기 또는 Ctrl/Cmd+C 안내를 제공한다. 자동 복사 실패를 성공으로 표시하지 않는다.
3. **상단 메뉴를 통한 화면 이동에 미저장 확인이 빠져 있었다.** 홈·주요 메뉴·튜토리얼 진입과 앱 내부 뒤로 가기에 확인을 적용했다. 취소하면 입력과 현재 화면을 유지한다. 내부 링크와 상위 메뉴가 연결되어도 확인은 한 번만 받는다.
4. **저장된 상대 메시지를 모두 지우면 미저장 변경으로 인식하지 못했다.** 빈 문자열로 수정한 경우와 관계·의도·목표 등 조건만 수정한 경우도 변경으로 취급한다.
5. **복사 요청 뒤 문장을 수정하면 이전 요청의 늦은 완료가 현재 문장의 완료처럼 보일 수 있었다.** 요청 당시의 편집 버전을 확인한다. 문장이 바뀌면 오래된 완료 안내를 버린다.
6. **연속 클릭과 저장 실패 후 재시도에 대한 사용자 관점 검증이 부족했다.** 요청 잠금으로 중복 실행을 막고, 저장 실패 시 입력을 남긴다. 재시도는 기존 기록 하나를 갱신하며 성공한 저장은 다시 수정하기 전까지 `저장됨`으로 표시한다.
7. **테스트가 통과해도 일부 JSDOM 포커스 오류를 실패로 처리하지 않았다.** React DOM을 가상 DOM보다 먼저 불러와 레거시 입력 이벤트 경로가 선택되던 초기화 순서를 수정했다. 테스트 중 처리되지 않은 JSDOM 오류가 발생하면 실패하도록 검증을 추가했다. 데이터 준비 중 React 업데이트가 테스트 대기 범위 밖에서 실행되던 경고도 수정했다. 이 보완 후 전체 테스트를 다시 실행했으며, 최종 테스트 로그에는 해당 오류와 React 경고가 없다.

복사는 클립보드에만, 저장은 이 브라우저의 IndexedDB에만 반영된다. 상대에게 메시지를 보내거나 카카오톡에 자동 연결하지 않는다. 계정 간·기기 간 동기화는 구현되어 있지 않으며, 브라우저 데이터 삭제 시 기록도 사라질 수 있다.

## 이번에 추가한 통합·회귀 시나리오

모두 통과했다. 5개 테스트 안에서 다음 분기를 함께 확인했다.

- 복사를 연속 두 번 눌러도 한 번만 요청 → 처리 중 표시 → 요청 중 답장 수정 → 이전 복사 완료가 새 답장에 표시되지 않음 → 저장 데이터는 변하지 않음.
- Clipboard API가 없는 환경 → 답장 전체 선택 및 포커스 → 버튼 근처 오류 안내 → 수동 복사 방법 제공 → 거짓 성공 및 AI 예시 안내 없음.
- 저장 지연 → 저장 중 표시 → 연속 클릭 차단 → 저장 공간 부족 오류 → 입력 보존 → 재시도 성공 → 기록 중복 없음 → 다시 편집하면 저장 버튼 재활성화.
- 전체 작업 화면에서 답장 작성 → 홈 이동 취소 → 뒤로 가기 이벤트 취소 및 현재 URL 복구 → 저장 → 대화 기록 목록 → 검색 → 다시 열기 → 수정 저장 → 같은 기록 유지 → 삭제 취소 → 삭제 확정.
- 저장한 상대 메시지 수정 화면에서 내용을 모두 지움 → 이동 취소 시 빈 입력 유지 → 내부 목록 이동 승인 시 확인 한 번 → 원래 저장 기록 유지.

기존 메신저 테스트도 다시 실행했다. 가상 예시 → 후보 선택 → 직접 수정 → 복사 → 저장 → 재진입, AI 한도 초과 후 수동 작성, 조건 변경 시 별도 기록 생성, 화면을 떠난 뒤 늦은 AI 응답 무시, 저장 실패 시 AI 호출 방지 등이 포함된다.

UI 테스트는 React를 JSDOM에 마운트하고 실제 컴포넌트의 버튼/입력을 조작했다. 데이터 저장은 fake-indexeddb, Clipboard·미디어·AI 공급자 응답은 테스트 대역을 사용했다. 실제 `putSession`으로 저장하고 목록 조회·재열기까지 연결한 경로와, 저장 지연/실패를 주입한 경로를 구분했다. 뒤로 가기 취소는 `popstate` 이벤트와 URL 복구를 확인했으며 실제 브라우저 히스토리 스택 조작과 동일하다고 주장하지 않는다.

Clipboard 검증 근거: `writeText`는 비동기 API이며 허용되지 않으면 거부될 수 있다. [MDN 영어 문서](https://developer.mozilla.org/en-US/docs/Web/API/Clipboard/writeText), [MDN 일본어 문서](https://developer.mozilla.org/ja/docs/Web/API/Clipboard/writeText).

**실제 브라우저 실행 차단:** 브라우저 점검 도구의 자동 승인 검토가 Codex 사용 한도로 완료되지 않아 동작 자체가 실행되지 않았다. 이는 Vercel 배포 한도와 별개다. 다른 도구로 승인 검토를 우회하지 않았다. 따라서 이번 수정본의 실제 화면 위치·크기, 운영체제 클립보드, 휴대폰 마이크, 새로고침 후 실제 브라우저 보존은 미검증이다.

**운영 반영:** 이번 검증은 수정 소스 기준이며, 운영 사이트에 이 변경이 배포되었다는 뜻이 아니다. Vercel 재배포와 운영 확인은 별도 진행해야 한다. 제한 해제 시각은 이번 작업에서 확인하지 않았으므로 특정 시각에 배포 가능하다고 보장하지 않는다.

## 배포 전후 남은 필수 확인

1. **데스크톱 Chrome·모바일 Safari/Chrome:** 예시 열기 → 후보 선택 → 답장 수정 → 복사 → 메모 앱에 붙여넣어 내용 일치 확인. 버튼 바로 아래 상태 안내가 스크롤 없이 보이는지 확인.
2. **실제 저장:** 답장 저장 → 목록에서 검색 → 재열기 → 페이지 새로고침 → 문장과 선택한 말투 유지 → 수정 저장 → 기록 중복 없음 → 삭제 취소/확정 확인.
3. **권한 오류:** 클립보드 사용을 거부한 환경에서 오류 문구와 수동 복사 동작 확인. 저장 제한 환경에서도 거짓 성공 안내 없이 입력이 남는지 확인.
4. **실제 뒤로 가기·모바일 스와이프:** 미저장 입력 후 홈/메뉴/뒤로 가기/새로고침의 취소와 승인 확인. 취소 시 입력·URL 유지, 승인 시 선택한 화면으로 이동 확인.
5. **실제 음성·AI:** 가상 대화만 사용해 녹음 중지 → 문자 확인 → 코칭, 외부 파일 → 문자 수정 → 화자 확인 → 분석을 각 1회 실행. 품질·지연과 실제 할당량 오류 메시지는 자동 테스트 결과와 구분해 기록.

이 항목을 통과한 뒤에 운영 사용자 관점의 최종 검증 완료로 표시한다.
