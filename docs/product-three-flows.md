# 든든콜 기능 구조 검토

기준: 2026-09-16, 운영 PR #33(d98b2a5)의 코드와 사용자·팀원 제안. 친구방 카드 표시 수정은 별도로 진행한다. 아래 제안은 기능 구현 완료를 뜻하지 않는다.

[현황 보충] 대표 흐름의 기능은 구현됐지만 첫 화면을 세 경로로 재배치하는 안은 아직 권고 단계다. 2026-09-16 장애 샘플 대응·동의 접기 구현과 외부 녹음 분석 가능성 검토는 `resilience-and-recording-analysis.md`를 참조한다.

[확정] 제품 소개의 중심 흐름은 ‘대화 연습 → 근거가 있는 복기 → 같은 장면 재연습’으로 둔다. 사용자가 이 방향에 동의했다.

[권고] 팀원이 제안한 세 기능은 대화 전·후·중의 진입 경로로 구조화한다. 공통 자산은 상대·상황·목표·지킬 선을 담은 카드, 음성·문자 기록, 근거가 연결된 코칭, 다음 연습, 업무 용어다.

| 기능 | 사용자 목적 | 권고 흐름 | 현행 제공 범위 |
|---|---|---|---|
| 대화 연습 | 실제 대화 전에 준비 | 상황·상대·목표 설정 → 음성/문자로 역할 연습 → 근거와 고쳐 말할 문장 → 해당 장면 재연습 | 구현·배포. 개인 연습에서 두 번 이상 답변한 뒤 복기. 인용문/발화 ID 검증, 결과 저장, 원래 목표·지킬 선 유지 |
| 녹음 돌아보기 | 이미 끝난 대화에서 배우기 | 녹음 첨부 → 문자/화자/내 역할 확인 → 목표와 평가 기준 설정 → 장면별 분석·코칭 → 연습 카드로 전환 | 부분 제공. 파일 저장·파형 재생·문자 변환·용어 스크랩은 지원. 외부 녹음 전체 분석, 화자 구분, 코칭→재연습 연결은 미구현 |
| 대화 중 힌트 | 대화 도중 다음 말을 준비 | 상황 카드 선택 → 짧은 상대 발화 입력 → 확인 질문/다음 문장 → 필요 시 녹음·복기로 연결 | 제한적 제공. 최대 8초씩 녹음→문자 변환→힌트. 연속 스트리밍, 같은 기기 통화음 직접 수집, 자동 화자 구분은 미지원. 코칭 내용도 자동 저장되지 않음 |

## 사용자에게 보이는 이름

[권고] ‘대화 연습 / 녹음 돌아보기 / 대화 중 힌트’로 표시한다. ‘프롬프트 제공’은 내부 구현 용어로 두고 화면에서는 ‘다음에 할 말’, ‘확인할 질문’처럼 바로 쓸 결과를 보여준다. 입력만 다르고 모두 같은 채팅창으로 끝나는 구조는 피한다.

- 연습: 상대 역할, 내 목표, 답변 후보, 실제 내 발화의 근거, 다시 말할 장면.
- 녹음 돌아보기: 내가 누구인지 확인하고 원문을 고친 뒤 분석. 근거를 누르면 원문과 연결. 초기 범위는 타임스탬프가 없는 문자 구간 연결부터 가능하며 정확한 음성 위치 재생에는 별도 정렬이 필요하다.
- 대화 중 힌트: 가장 필요한 한 문장과 확인 질문을 먼저 표시. 말할지 결정하는 사람은 사용자. 수집·처리 중 상태와 입력 실패 재시도를 명확히 안내한다.
- 친구방·용어 노트·내 기록: 세 흐름을 지원하는 공통 공간. 친구방을 대화 연습과 동등한 제품 핵심 목적처럼 소개하지 않는다.

## 판단이 필요한 두 지점

| 옵션 | 효과 | 비용·의존성 | 위험·검증 |
|---|---|---|---|
| A. 세 기능을 첫 화면에 동등하게 노출 | 선택의 폭이 보임 | 세 경로의 완성도·오류 안내를 함께 확보해야 함 | 미완성 녹음 분석 및 실시간 기대가 커질 수 있음. 처음 온 사용자가 목적에 맞게 진입하는지 확인 |
| B. 연습을 대표 진입으로, 녹음·대화 중 힌트를 보조 진입으로 제공 [권고] | 시연의 핵심 가치가 선명하고 이미 구현한 흐름 활용 | 녹음 분석을 단계적으로 연결. 화면 개편의 추가 공수는 상대적으로 작음 | 보조 진입을 찾기 어려워지지 않도록 버튼과 상태 표시. 각 경로 발견·완료율 확인 |

실시간 범위: 초기에는 현재의 ‘짧게 듣고 한 문장 힌트’를 명확히 표시하는 안을 권고한다. 연속 청취는 음성 구간 분리, 끼어들기/취소, 지연, 비용, 동의·보관 범위를 포함한 별도 과제다. 현재 성능을 연속 실시간 코치로 표현하지 않는다.
