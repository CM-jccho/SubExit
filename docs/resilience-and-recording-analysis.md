# 권고안 현황·외부 녹음 분석·해커톤 예비 응답

기준일: 2026-09-16. 기준 코드: 운영 d45f184 + 이번 장애 대응/동의 접기 변경. 이 문서에서 ‘구현’은 코드·자동 검증을 완료한 범위이며, 실제 AI의 분석 정확도 검증과 구분한다.

## 2. 외부 녹음 분석은 어려운가

[판단] 구현 가능한 기능이다. 기존 파일 처리·음성 전사·기기 저장을 활용할 수 있다. 핵심 난점은 분석 API 한 번 호출보다 **분석 대상이 누구의 말인지, 무엇을 기준으로 평가할지, 어떤 원문이 근거인지 확인하는 과정**이다.

| 옵션                              | 제공 범위                                                                                                               | 의존성과 검증                                                                                                                               | 권고                                                              |
| --------------------------------- | ----------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| A. 짧은 녹음의 확인된 문자로 분석 | 현행 파일 제한(2분·2.4MB) 유지 → 전사 수정 → 내 말/상대 말 구간 확인 → 상황·목표 확인 → 인용 기반 코칭 → 한 장면 재연습 | 녹음 분석 전용 입력/출력 계약, 원문 인용 검증, 분석 결과 저장과 수정 시 무효화, 한 장면을 연습 데이터로 전환하는 UI 필요                    | 다음 개발로 권고. 자동 화자 인식의 오류를 사용자가 확인할 수 있음 |
| B. 자동 화자 구분·시간 표시       | A에 화자별 전사와 구간 재생 추가                                                                                        | Gemini는 기능상 가능하나 서로 말이 겹치거나 소음이 있을 때 실파일 평가 필요. ‘화자 A’와 ‘나’의 매핑은 사용자 확인. 시각 정렬 오차 검증 필요 | A 이후 검증 결과에 따라 확대                                      |
| C. 긴 통화 전체 분석              | 긴 파일의 분할·비동기 처리·진행률·부분 재시도                                                                           | 현재 20초 모델 요청/30초 라우트·파일 크기 제한을 넘는 작업 구조 필요. 청크 경계, 중복 전사, 처리 비용, 취소·삭제를 설계해야 함              | 해커톤 1차 범위에서 분리 권고                                     |

[구현 시 주의] 기존 `/api/review`는 AI 역할 연습의 번갈아 말하는 구조와 사용자 발화 2개 이상을 전제로 한다. 외부 전사를 그대로 끼워 넣으면 화자나 발화 순서를 잘못 평가할 수 있다. 녹음 분석 전용 구간 ID·화자·원문 계약을 만들고 인용 검증 로직을 공통으로 활용하는 편이 타당하다.

[완료 기준] 원본/전사를 수정해도 이전 결과를 최신 분석처럼 보이지 않게 함; 모든 인용이 실제 확인된 원문에 존재; 자기 발화에 대한 코칭만 수행; 분석 실패 시 파일 보존; 같은 장면으로 전환한 연습에 원래 목표·상대 말을 유지. 담당·일정은 미정이다.

[현행 조건] 운영은 개인정보 없는 자작 대화를 보내는 Gemini 샘플 전송 모드다. 실제 업무/고객 녹음 적용에는 데이터 처리 설정과 참여자 동의를 별도로 정해야 한다. 이번에 유료 전환·보관 정책 변경은 하지 않았다.

## 3. 장애 대응의 동작

| 발생 조건                                   | 화면 동작                         | 재시도                                                                               |
| ------------------------------------------- | --------------------------------- | ------------------------------------------------------------------------------------ |
| 제공자가 일일 한도라고 명시                 | ‘사전 작성 샘플 · 일일 한도 초과’ | 태평양 자정을 계산하여 한국 날짜·시각 표시. 서머타임 반영                            |
| 분당 한도/앱 요청 한도                      | 원인을 구분한 샘플 표시           | 제공자의 대기 시간 또는 보수적 기본 대기 시간 표시                                   |
| 한도 종류 미확인 429                        | ‘AI 사용 한도 초과’               | 일일 한도로 단정하지 않음. 재시도 권장 시점과 정확한 초기화 시각은 알 수 없다는 안내 |
| 연결 실패/시간 초과/서비스 오류/잘못된 응답 | 원인에 맞춘 샘플 또는 오류 안내   | 연결 오류는 잠시 후 재시도. 응답 형식 오류도 AI 분석 성공으로 처리하지 않음          |
| 동의 누락/입력 오류/크기 초과/권한 거부     | 원래 오류 유지                    | 입력이나 동의를 고친 뒤 재시도. 샘플로 오류를 덮지 않음                              |
| 사용자가 ‘샘플로 연습하기’ 선택             | ‘샘플 모드’ 표시, AI 호출 없음    | 체크 해제 후 AI 전송에 동의하면 실제 AI 요청. 기존 장애 대기 시간은 유지             |

- 예비 문장은 상황의 키워드로 분류한 뒤 같은 문장을 되풀이하지 않도록 고른다. 현재 대화의 의미나 목표 달성 여부를 AI로 분석한 결과가 아니다.
- 오류 후 대기 상태는 해당 탭의 sessionStorage에 이유·시각만 저장한다. 개인 대화 내용은 넣지 않는다. 반복 API 호출을 줄이고 대기 시간이 지나면 다시 실제 요청을 허용한다. 모든 사용자/기기 전체의 호출을 제어하는 서버 분산 제한 장치는 아니다.
- 저장된 샘플 답변은 각 발화에 버전·샘플 ID·상황·오류 유형·재시도 시각을 보존한다. 후보에도 샘플 표시가 붙는다. 재연습으로 가져간 발화와 문자 내보내기에도 샘플 출처를 남긴다.
- 음성 전사·실제 복기·용어 뜻·상황 설정 결과는 일반 문장으로 대체하지 않는다. 음성 인식 실패 시 원본과 재시도/직접 입력을 남긴다. 복기 실패 시 별도의 가상 대화 예시와 직접 확인할 질문을 보여주며 현재 기록에 분석 결과를 만들지 않는다.
- 샘플 모드의 음성은 AI 문자 변환 없이 녹음·재생까지만 가능하다. 대화에 사용할 문자는 직접 입력해야 한다. 실제 AI 음성 코칭이 작동하는 것처럼 시연하지 않는다.
- 대화 중 힌트는 원래대로 자동 저장되지 않는다. 화면의 샘플 표시를 남기되 저장됐다고 주장하지 않는다.

## 4. 확보한 데이터와 시뮬레이션

- `data/demo-responses.json`: 8개 상황, 예비 문장 128개(첫마디 24·상대 응답 32·답변 후보 24·코칭 표현 24·친구 도우미 문장 24), 가상 복기 예시 8개.
- 상황: 부탁하기, 일정 조율, 업무 범위 조율, 정중한 거절, 면접·발표, 피드백, 친구 대화, 일반 대화.
- 전부 이번 작업에서 사전 작성한 가상 내용이다. 사용자 실제 녹음이나 Gemini 출력의 수집본이 아니다.
- `fixtures/ai-outages.json`: 15개 장애/입력 오류 조건.
- `node scripts/simulate-ai-outages.cjs`: 8개 상황 × 4개 기능 × 15개 조건 = 480개 조합 검증. 외부 AI 호출 없이 재현한다.
- `docs/validation/ai-outage-simulation.json`: 실행 시각, 조합별 검증 수, 대표 예비 문장, 제한 사항 기록.
- 추가 자동 검증: 겨울/여름/서머타임의 초기화 시각, 후보 중복 회피, 대기 중 중복 호출 차단과 만료 후 AI 복귀, 저장·재진입 후 출처 유지, 동의 펼치기·철회, 복기 오류 시 분석 결과 미생성, 진행 중 이탈 시 잘못된 기록 저장 방지.

[한계] 480개는 제어 흐름과 데이터의 시뮬레이션 통과 수다. 실제 AI 품질·음성 정확도·휴대폰 호환성 또는 사용자의 대화 능력 개선률을 뜻하지 않는다.

## 5. 해커톤 시연 순서

1. 연결이 정상이라면 자작 대화로 실제 AI 연습과 복기를 짧게 시연한다.
2. 오류가 나면 표시된 원인과 한국 시간 재시도 안내를 보여준다. 예비 응답이 샘플이라는 점을 설명한다.
3. 화면/저장/후보 선택을 반복 확인할 때는 ‘샘플로 연습하기’를 켠다. AI 한도를 소비하지 않는다.
4. 복기 오류 때는 ‘가상 대화의 복기 예시’를 별도 예시로 보여준다. 실제 분석이 완료됐다고 설명하지 않는다.
5. 음성·실모델의 실제 동작 확인은 별도로 짧게 수행한다. 시뮬레이션을 실제 호출 성공률로 제시하지 않는다.
