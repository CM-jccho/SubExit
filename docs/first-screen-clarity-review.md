# 첫 화면·전체 목록 전환 재검토

## 실제 운영 화면에서 확인한 문제

- 홈의 큰 소개 문구와 캐릭터가 실제 연습 예시보다 먼저 보인다.
- 상단 ‘전체 둘러보기’를 눌러도 홈은 예시 2개만 표시한다. 전체 목록이 아닌 추천 카드 교체라 변화가 약하다.
- ‘전체를 보는 중 · 내 선택’은 현재 표시 범위와 저장한 관심 상황을 혼합한다.
- 전역 전체보기 상태가 다른 화면의 추천 범위까지 바꾼다.

## 수정한 동작

- 첫 방문: 짧은 질문과 4개 상황 선택. 분야별 색·소품을 넣은 가로형 카드에 그림을 집중하고 큰 안내 장면은 제거.
- 선택 후 홈: 짧은 제목 → 관련 연습 카드 → 녹음 분석·메시지 답장 순서. 독립된 큰 캐릭터 영역 제거.
- 홈 ‘모든 연습 상황 보기 (실제 예시 수)’: 내 대화의 전체 목록으로 이동. 제목도 ‘모든 연습 상황’으로 변경.
- 전체 목록: 내가 만든 대화와 업무·고객 응대·학부모 상담·친구와 가족 예시를 구분. 분야별 실제 표시 개수 노출.
- 목록 안에서 ‘관심 상황 예시 N / 모든 분야 예시 N’ 선택 상태를 표시. 검색 결과는 해당 범위에서 계산.
- 관심 상황은 저장 상태를 유지. 전체보기는 대화 목록에만 적용하며 홈·용어 노트·AI 상대 추천에 전파하지 않음.
- 삭제한 예시를 다시 만들거나 개인 대화를 필터에서 숨기지 않음.

## 검증

- 근거 검사 회귀 항목을 포함한 테스트 127개 통과.
- 확장한 통합 테스트에서 확인: 최초 선택, 선택 저장, 개인 카드 유지, 전체 목록 진입, 4개 분야 구분, 7개 예시와 1개 개인 카드 표시, 선택 범위 복귀, 홈 복귀 시 관심 상황 복원, 새로고침, 삭제한 예시 미복구.
- 최종 프로덕션 빌드 및 타입 검사 통과.
- 실제 운영 화면의 문제는 브라우저에서 재현. 수정 화면의 브라우저 시각 검증과 실제 휴대폰 터치는 아직 완료하지 못함.
- 운영 반영은 이전 PR 병합 자동 승인 검토에서 차단된 상태. 승인 없이 운영 브랜치를 변경하지 않음.

## 참고한 UX 원칙

변화가 일어났다는 문구만 보여주기보다 사용자가 결과를 확인할 수 있어야 한다. 이번에는 이동할 목적지를 버튼에 명시하고, 이동 후 제목·분야·개수로 표시 범위를 확인하도록 적용했다. [NN/g: Visibility of System Status](https://www.nngroup.com/articles/visibility-system-status/)

영문 자료와 함께 일본 디지털청의 버튼 컴포넌트 문서도 참고 대상으로 확인했다. [デジタル庁: ボタン](https://design.digital.go.jp/dads/components/button/)

## 추가 검토: AI slop과 기호접지

범위는 첫 화면의 표현, 코칭·복기·검색의 근거 연결, 연습 보상의 의미다. 미적 취향만으로 AI slop을 판정하지 않고, 실제 과업과 연결되지 않는 장식·반복·포괄적 문구·확인되지 않은 결과를 품질 저하 요인으로 보았다. 엄밀한 의미의 기호접지 전체를 검증한 것은 아니다. 이번 검토는 인터페이스의 기호-행동 연결과 AI 출력의 입력/출처 연결을 확인한다.

### 확인된 약점과 수정

- [근거/해석] 큰 캐릭터는 홈에서 상태나 행동을 설명하지 않고 면적을 차지한다. 대화 연습으로 이어지는 카드 안의 작은 장면으로 이동했다.
- [근거] 전체보기는 화면 제목이 유지된 채 예시 2개만 교체했다. 이제 목록으로 이동하고 분야·개수·선택 상태가 바뀐다.
- [근거] `validateCoach`는 원문과 연속 일치하지 않아도 단어 절반 정도가 일치하면 인용을 허용했다. ‘환불 불가’를 ‘환불 가능’으로 바꿔도 나머지 단어가 겹치면 통과할 수 있다. 공백 차이만 허용하는 연속 인용 검사로 수정했다.
- [수정] 짧은 코칭 상세에서 ‘상대 말에서 확인한 표현’과 ‘AI의 제안 이유’를 분리해, 인용과 해석을 같은 사실처럼 읽지 않도록 했다.

### 이미 입력·행동과 연결된 부분

- `practice-review.ts`: 사용자 turn ID와 실제 인용을 검사하고, 현재 맥락·발화로 만든 키를 통해 이전 복기를 새 대화에 잘못 적용하지 않도록 한다.
- 같은 장면 재연습: 지적된 사용자 답변의 실제 앞 대화로 돌아가며 목표와 지킬 선을 유지한다.
- 외부 녹음 분석: 사용자가 확인한 문자와 화자를 대상으로 분석한다. 녹음의 표정·정서·억양을 이해했다고 볼 수는 없다.
- 샘플 대체 응답: ‘사전 작성 샘플’로 구분하고 현재 입력에서 추출한 근거를 꾸며 넣지 않는다.
- 연습 스탬프: 실제 작성·복기·재연습과 연결하며 샘플이나 후보 그대로의 입력은 일부 획득 조건에서 제외한다. 이는 수행 기록이지 대화 능력 향상을 측정한 점수가 아니다.
- AI 요청 연습: 규칙 기반 검사는 ‘표현 찾음’으로 표시한다. 의미적 정답 판정이 아니다.

### 남은 한계와 선택지

- [P1, 확인 필요] 인용이 원문에 있다고 AI의 해석이나 제안까지 맞는 것은 아니다. 목표 유지, 부정어, 약속 범위, 근거 부족 응답을 별도 평가해야 한다. 실제 모델 출력에 대한 신규 품질 측정은 이번에 수행하지 않았다.
- [P2, 해석] 복기 구조에 ‘잘한 점’이 필수라 근거가 부족한 답변에서도 칭찬을 만들도록 압박할 수 있다. 다음 개선에서는 ‘판단 보류’ 또는 ‘유지할 행동을 찾기 어려움’을 허용하는 구조를 권고한다. 이번에는 출력 계약을 변경하지 않았다.
- [P2, 근거] 최근 표현 검색은 검색 메타데이터·출처 링크·인용 구간 존재를 검사하지만 모든 주장에 출처가 있는지, 원문이 그 해석을 뒷받침하는지까지 보장하지 않는다.
- [P2, 해석] 캐릭터 종류만으로 교사·고객·동료 역할은 전달되지 않는다. 카드 제목/분야/실제 상황을 함께 보여주며 캐릭터 자체를 역할 증명으로 사용하지 않는다.

권고 순서는 A) 이번의 UI 연결·인용 검사 보완 → B) 동일 장면에서 맥락을 바꾼 반례 중심의 AI 품질 평가 → C) 별도 평가 모델 추가 여부 결정이다. B는 비용과 지연 증가 없이 약점을 먼저 확인할 수 있다. C는 평가 비용·지연과 평가 모델의 오류도 발생하므로 현 단계에서 추가하지 않는다.

후속 수용 기준: 샘플과 실제 결과의 출처를 사용자가 구분할 수 있음, 전체보기에 포함된 범위를 설명할 수 있음, 문장 부정/단어 재조합/추가 사실을 인용으로 수용하지 않음, 근거가 부족한 경우 능력이나 감정을 단정하지 않음. 마지막 항목은 실제 모델 평가가 남아 있다.

검색 기반 grounding은 외부 자료와 답변을 연결하는 수단이다. 이것만으로 해석의 타당성 전체가 입증되는 것은 아니므로 입력 인용·AI 해석·외부 출처를 구분했다. [Google 공식 영문 문서](https://ai.google.dev/gemini-api/docs/google-search), [일본어 문서](https://ai.google.dev/gemini-api/docs/google-search?hl=ja)

인용 검사 강화로 모델이 원문을 의역해 반환하면 기존보다 오류가 더 자주 표시될 수 있다. 원문에 없는 인용을 근거로 표시하는 대신 기존 오류/샘플 안내 경로로 처리한다.
