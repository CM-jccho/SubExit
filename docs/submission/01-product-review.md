# 든든콜 제품 재검토와 추천안

검토 대상: 첨부 `든든콜-산출물.zip`, 기존 운영 데모, CM-jccho/SubExit. 초기 소스 `9d7ee28`, 최종 통합 기준 `8e8ca4b` (#23). 첨부의 기획·UX·디자인·데모·제출 자료 16개 Markdown과 링크 목록을 앞선 작업에서 읽고, 중첩 tgz의 15개 문서가 바깥 문서와 동일함을 확인했다. 이후 작업 환경에서 임시 파일이 사라져 최신 원본과 남아 있는 분석 기록으로 코드를 복구했다. 아래 검증은 복구 코드에 대해 다시 실행했다.

## 판단

**추천: 실제 대화의 다음 한 문장 보조를 핵심으로, 연습을 보조 흐름으로 둔다.** 영업 전화 수신자의 거절을 첫 시연 사례로 좁힌다. 사용자 조사 전이므로 문제 빈도·전환율·불안 감소 효과는 가설이다.

| 선택안 | 장점 | 제약 | 예선 판단 |
|---|---|---|---|
| A. 연습 중심 | 키 없이 안정적인 시연, 작은 개발 범위 | 학습 앱과의 차별성 약함 | 보조 기능으로 유지 |
| B. 짧은 마이크 입력 + 한 문장 코칭 | 실제 대화 순간의 필요를 보여줌 | 전사·생성 지연, 화자 확인 필요 | 이번 구현의 추천안 |
| C. 같은 휴대폰 통화 직접 연동 + 상시 코칭 | 최종 경험에 가까움 | OS 통화 오디오 접근, 백그라운드, 지연·비용 부담 | 예선 이후 별도 기술 검증 |

B는 C가 완성된 것처럼 보이는 화면을 만드는 것이 아니다. 최대 8초 입력 후 마이크를 끄고 전사·생성한다. 실제 통화 옆에서 쓸 수 있는지는 실제 기기의 오디오, 소음, 지연 측정 이후 판단해야 한다.

## 기존 산출물과 구현의 주요 차이

| 관찰 | 제품 영향 | 이번 변경 |
|---|---|---|
| 일부 문서는 연습·녹음 분석, 일부는 실시간 코치를 강조 | 심사자가 무엇이 핵심인지 파악하기 어려움 | 홈 최우선 버튼을 '지금 대화 코칭'으로 통일 |
| 과거 데모는 마이크 없이 녹음 중처럼 표시 | 실제 AI 구현 범위를 오해할 수 있음 | 샘플 시연과 실제 마이크 상태 분리 |
| 기존 analyze-call은 실제 업로드도 fixture 결과를 돌려줌 | 업로드한 음성 분석으로 오인 | 기존 실음성 분석 501, 새 짧은 음성 API 구현 |
| pressure 우선 매핑 및 일반 거절 멘트 재사용 | 면접 등 목표에 맞지 않는 대응 | 7개 상황의 목표·예시 별도 작성, 서버에 목표 전달 |
| 샘플을 본 뒤 개인 버팀률·XP처럼 보상 | 연습 없이 능력 상승처럼 보임 | 직접 작성·자기 점검·수정에만 참여 보상 |
| 초기 배포의 demo 쿼리가 홈에 머묾 | 심사 진입이 복잡함 | 작업 중 #23에서 자동 진입 수정 확인, 새 구현도 유지 |

원본을 모두 폐기하거나 새 레포로 분리할 근거는 약하다. 기존 레포의 새 브랜치/PR로 기능과 문서를 함께 검토하는 편이 추적에 유리하다. 초기 GitHub 쓰기는 저장소 접근 누락으로 차단되어 적용 패치를 제공했다. 이후 사용자가 SubExit 접근을 추가해 원격 PR 작업을 재개했다.

## 말해보카에서 참고할 것

[말해보카 공식 앱 소개](https://play.google.com/store/apps/details?hl=ko&id=kr.epopsoft.word)의 짧은 학습 단위, 예시·피드백, 반복 학습, 캐릭터를 흐름 관점에서 참고했다. 화면·캐릭터를 복제하지 않았다.

- 한 화면에서 다음 행동을 하나로 좁힌다: 상대 말 → 내 답변 → 자기 점검 → 고쳐 쓰기.
- 예시를 곧바로 정답처럼 주기보다, 내 문장을 먼저 써보거나 필요할 때 열게 한다.
- 캐릭터는 친근함을 보조한다. 실제 대화 중에는 코칭 문장의 시인성이 먼저다.
- 과한 네온·그라데이션·일률적인 AI 카드 문법을 줄인다. 밝은 종이색 바탕, 짙은 녹색 코칭 영역, 짧은 문구와 일관된 버튼을 사용한다.
- 모바일은 하단 3개 메뉴, 데스크톱은 왼쪽 메뉴. 실시간 코칭 결과가 오면 작은 화면에서는 결과 위치로 이동한다.

[Duolingo 공식 스트릭 설명(영문)](https://blog.duolingo.com/how-duolingo-streak-builds-habit/)은 반복 행동을 만드는 흐름의 참고다. 이 제품에서는 연속 기록을 유지하되 하루를 놓쳐도 누적 XP는 사라지지 않게 했다. 학습 앱의 습관 효과가 든든콜에서도 검증되었다는 뜻은 아니다.

## 게이미피케이션 기준

| 행동 | 보상 | 근거 |
|---|---|---|
| 샘플 보기 | 없음 | 내 답변이 없음 |
| 5자 이상 답변 + 자기 점검 2개 | 10 XP | 연습 시도 자체를 기록 |
| 기존 답변과 다른 문장으로 수정 | 5 XP | 재시도 유도 |
| 실제 대화 코칭 | 없음 | 대화 중 경쟁·점수 부담 최소화 |

같은 날 같은 구간별 한 번만 지급한다. 정답률, 버팀률, 사회성 점수, 타인과의 순위는 제공하지 않는다. 자기 점검은 객관적인 평가가 아니며 사용자가 허위로 체크할 수 있다. 이를 막기 위한 과도한 감시보다 '참여 기록'이라는 정확한 의미를 유지한다. localStorage는 수정 가능하므로 공식 인증 기록으로 사용할 수 없다.

## AI 및 마이크 설계

`MediaRecorder → 완결된 짧은 파일 → Gemini 전사 → 상대 말 확인 → Gemini 코칭`.

[Gemini 음성 이해 문서(일문)](https://ai.google.dev/gemini-api/docs/audio?hl=ja), [getUserMedia 문서(일문)](https://developer.mozilla.org/ja/docs/Web/API/MediaDevices/getUserMedia)를 참고했다. 단일 기기의 전화 오디오 캡처를 약속하지 않는다. 상대·내 목소리 혼합과 통화 수신 중단은 기기 검증 대상이다.

기본은 전사 확인 후 생성한다. '확인 없이 바로 코칭'은 사용자가 선택할 수 있지만 화자 혼동이 생길 수 있다. 모델의 원문 인용은 실제 입력에 있는지 검사한다. 인용이 맞아도 해석과 대응 적합성까지 보장하지 않으므로 최종 문장은 사용자가 판단한다.

## 다음 제품 실험: 제안이며 미실행

1. 영업 권유 샘플 20개로 전사 정확성, 목표에 맞는 한 문장 여부, 원음 종료→표시 지연을 측정한다.
2. 5명 내외에게 대화 중 한 문장 읽기가 실제로 가능한지 관찰한다. 화면을 보느라 상대 말을 놓치는지도 기록한다.
3. 단순 '지금 답하기 어렵습니다' 고정 문장 대비 AI 코칭이 유용한 상황의 비율을 비교한다.
4. 실측 결과가 충분할 때 VAD·스트리밍·문장 유지 시간·갱신 억제 등으로 확장한다.

해커톤에서 강조할 것은 과장된 실시간 성능보다 실제 입력에 따라 바뀌는 문장과 그 근거다.
