# 스픽코칭 · 대화 중 다음 한마디

**대화 중에는 다음 한마디를 돕고, 평소에는 같은 상황을 연습합니다.**

운영 주소: https://ddeundeun-call-render.onrender.com/

새 브랜드 주소: https://speakcoaching.onrender.com/ — Gemini 설정과 자작 샘플 코칭 확인 완료. 기존 브라우저 기록은 이전 주소에서 확인합니다. [주소 전환·배포 기록](docs/deployment/speakcoaching-brand-2026-09-17.md)

핵심은 **대화·통화 중 막히는 순간에 다음 한마디를 돕는 AI**입니다. 핵심 기능은 대화 연습, 녹음 첨부·분석·코칭, 실시간 음성 기반 프롬프트(다음 말 힌트)의 세 가지입니다. 홈은 ‘지금 대화 도움받기’를 가장 강조하고 ‘미리 연습하기’와 ‘녹음 분석·코칭’도 바로 제공합니다. 같은 상대·상황·목표·지킬 선을 실전 도움과 평소 연습에 재사용합니다. 지원 브라우저에서는 Web Speech API의 연속 인식과 중간 자막을 사용하고, 확정된 최근 1,000자에 대한 코칭을 별도로 요청합니다. 음성 인식은 코칭 처리 중에도 유지합니다. 미지원 브라우저에는 최대 8초 녹음·직접 입력 방식을 제공합니다. 같은 휴대폰의 통화 음성을 직접 가져오지는 않습니다. 실전 입력·결과의 자동 장기 기록도 현재 제공하지 않습니다.

평소에는 AI 상대와 연습 → 실제 발화에 근거한 복기 → 같은 장면 재연습으로 이어집니다. 녹음 분석·코칭도 홈에서 독립적으로 시작하며, 기초 훈련은 복기 후 필요한 기술을 보강합니다. 메시지 답장·용어·상대 설정·사용 안내는 더보기에 둡니다. AI 요청·일상 대화·커뮤니티·대화 관찰은 해커톤의 주 동선에서 제외하고 기존 기록/주소는 보존합니다.

카드와 관심 설정은 localStorage, 저장한 대화·음성 원본·용어·답장 등은 IndexedDB를 사용합니다. 모두 해당 주소의 브라우저 안에 저장되며 계정·기기·호스팅 주소 간 자동 이전은 없습니다. 카드 설정 대화 전문은 저장하지 않습니다. 기능별 내려받기를 지원하지만 전체 일괄 백업·복원은 지원하지 않습니다.

API 키 없이도 샘플·수동 작성·일부 훈련을 이용할 수 있습니다. 실제 AI 처리와 사전 작성 예시는 구분합니다. 키가 설정돼도 할당량이나 응답 검증 오류로 AI 요청이 실패할 수 있습니다.

## 실행

Node.js 20.9 이상에서:

```bash
npm ci
cp .env.example .env.local
npm run dev
```

- `/`: 지금 대화 도움받기, 미리 연습하기, 녹음 분석·코칭, 최근 개인 기록 한 건
- `/?demo=1`: 카드 맥락과 코칭 문장의 관계를 보여주는 샘플
- `/?live=1`: 실전 도움 목적을 유지한 상황 선택부터 시작
- `/evidence`: 구현 범위·데이터 처리 설명

API 키 없이 샘플과 직접 연습을 사용할 수 있습니다.

## Gemini 무료 API 연결

[Google AI Studio](https://aistudio.google.com/)에서 API 키를 발급받고 서버 환경변수에만 설정합니다. 키를 채팅·GitHub·브라우저에 붙여 넣지 마세요.

최소 설정은 Production의 비밀 환경변수 `GEMINI_API_KEY` 하나입니다. 키가 있으면 카드 정리·코칭·짧은 음성을 활성화합니다. 아래 나머지 값은 선택 설정이며, 기존 `COACH_AI_ENABLED=false` 또는 `COACH_VOICE_ENABLED=false`가 있으면 해당 비활성화 설정을 존중합니다. 사용자의 전송 확인 조건은 계속 적용됩니다.

```dotenv
GEMINI_API_KEY=서버에만_설정
GEMINI_MODEL=gemini-2.5-flash
COACH_AI_ENABLED=true
COACH_VOICE_ENABLED=true
GEMINI_DATA_MODE=free
```

로컬은 `.env.local` 저장 후 재시작하고, Render는 서비스의 Environment에서 키를 설정한 뒤 재배포합니다. 기존 Vercel 환경변수는 Render로 자동 복사되지 않습니다. 모델 접근 여부·할당량은 해당 AI Studio 계정에서 확인해야 합니다. 무료 모델의 한도와 정책은 변할 수 있습니다.

`GET /api/coach`의 `configurationStatus`로 설정 상태만 확인할 수 있습니다. `missing_key`는 해당 배포에 키 없음, `disabled`는 키가 있지만 AI 비활성화, `configured`는 설정 완료입니다. 키 값은 반환하지 않습니다. `configured`만으로 유효한 키·할당량·AI 응답이 검증된 것은 아니며, 실제 자작 샘플 요청으로 확인해야 합니다.

무료 모드는 **만 18세 이상, 개인정보·기밀 없는 자작·샘플 대화**에만 사용합니다. Google 무료 API 입력·출력은 제품 개선과 검토에 이용될 수 있습니다. `GEMINI_DATA_MODE=paid`는 화면 안내와 서버 확인 조건을 바꾸는 값으로, 실제 Google 과금 등급을 변경하지 않습니다. 실제 대화 적용 전 계정의 데이터 처리 조건과 참여자 동의를 확인하세요.

## 카드 선택 후 코칭 동작

1. 저장한 카드의 목표와 말투, 전송 안내 확인.
2. 지원 브라우저: 별도 음성 인식 서비스 전송 동의 후 연속 듣기 시작.
3. 중간 자막을 즉시 표시하고, 확정된 최근 1,000자를 코칭 요청으로 묶음. 원음은 브라우저 음성 인식 서비스가 처리하고 Gemini에는 인식된 문자와 선택한 카드만 전송.
4. 요청은 한 번에 1개, 대기 스냅샷은 최신 1개로 합침. 최초 확정 후 650ms 안정화, 반복 요청은 최소 6초 간격(기존 분당 12회 한도 이내). 코칭 오류 시 자막은 유지하고 자동 재시도는 중단.
5. 기존 제안을 유지하며 다음 제안으로 갱신. 아직 최신 말이 반영되지 않은 제안은 표시. 중지·언마운트·화면 비활성화 시 음성 인식과 AI 요청 취소, 늦은 응답 무시.
6. 짧게 녹음·직접 입력: 기존 8초 녹음 후 전사·코칭 방식 유지. 이 방식에서만 처리 중 마이크를 끔.

대면 또는 **다른 기기의 스피커폰 옆**에서 사용합니다. 같은 휴대폰의 전화 음성을 직접 가져오거나 화자를 자동 구분하지 않습니다. 연속 인식은 브라우저·네트워크에 따라 재연결이나 인식 지연이 발생하며, 화면 잠금·백그라운드에서 중단합니다. Web Speech API 기반이며 Gemini Live API 연결로 오인해서는 안 됩니다. 자막 표시와 AI 코칭 지연은 별도로 검증해야 합니다.

주요 연습 화면의 보상은 직접 답하기 → 고쳐 쓰기 → 같은 장면 재연습에 따른 꾸미기 티켓·장면 스탬프·기념품입니다. 반복 저장·샘플 열람으로 보상을 중복 지급하지 않습니다. 이전 `/practice`의 XP는 별도 레거시 화면이며 현재 핵심 보상 체계를 설명하지 않습니다.

## 호환성과 운영 범위

기존 `UploadForm` 등은 비교용으로 남겨두었지만 새 루트에서는 사용하지 않습니다. `/api/analyze-call`은 실제 파일 분석 대신 501을 반환하고 명시적인 샘플 안내만 지원합니다. 현재 외부 녹음 분석은 `/api/transcribe`와 `/api/recording-review`를 사용합니다. 녹음 분석 업로드는 30분·50MB, 문자 60,000자·600개 발화까지이며 브라우저에서 16kHz 모노 WAV의 45초 구간으로 변환해 순차 전사합니다. 개별 API 요청은 기존 2.4MB 한도 이내입니다. 이미 압축된 원본보다 WAV의 총 전송량은 늘 수 있습니다. 원본은 별도 보관하고 성공한 구간의 문자와 진행 상태로 재시도를 이어갑니다. 완료되지 않은 부분을 완료된 전문처럼 표시하지 않습니다. TXT·SRT·VTT 가져오기는 외부 AI 호출 없이 가능합니다. 화자 표시는 사용자가 확인하며, 명시적인 ‘나:’·‘상대:’ 접두어만 자동 반영합니다. 이전 분석 응답 계약과 다릅니다. `/api/analyze`는 구독 화면 분석의 기존 코드이며 새 코칭 경로에서 호출하지 않습니다.

음성·코칭 API는 Gemini만 호출합니다. 실패 시 다른 유료 제공사로 전환하지 않습니다. 서버 요청은 크기 제한, 시간 제한, 원문 인용 검증을 적용합니다. 요청 제한은 인스턴스별 IP당 분당 12회이며 분산 배포 전체의 한도를 보장하지 않습니다. 공개 트래픽 전에는 중앙 제한/일별 예산 관리가 필요합니다.
